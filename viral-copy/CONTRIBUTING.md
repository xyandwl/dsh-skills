# 贡献指南

这个仓库的价值不在「写得多」，在「写得具体」。所以贡献标准只有一条：**每个主张后面跟一个可执行的东西。**

## 欢迎的 PR

| 类型 | 说明 | 门槛 |
| --- | --- | --- |
| 扩词库 | 往 `references/banned-words.txt` 加行业违禁词 | 一行一条，格式 `词\|类别\|替换建议` |
| 新平台参考 | B 站、知乎、公众号、TikTok、LinkedIn | 必须含「平台逻辑 + 结构模板 + 常见翻车点」三节 |
| 新案例 | 往 `examples/` 加真实爆款拆解 | 必须带数据（曝光/收藏/涨粉）与「做对了什么」 |
| 修规则 | 平台政策变了，更新 `platform-rules.md` | 附来源链接或截图 |
| 脚本改进 | `check_banned_words.py` | 保持零依赖、不联网 |

## 不接受

- 只改措辞、不改信息的润色
- 没有数据支撑的「爆款方法论」
- 引入第三方依赖（这个仓库的核心卖点之一是零依赖）
- 任何形式的自动发布/刷量脚本

## 词库格式

```
词|类别|替换建议
```

- `类别` 用现有分类：`绝对化` `功效` `金融` `教育` `导流` `其他`
- `替换建议` 要写成**可直接用的替代句**，不要写「建议修改」
- 长词优先匹配由脚本自动处理，不用手动排序

## 提 PR 前自查

- [ ] 没有编造案例数据
- [ ] 新增文件已加入 `README.md` 的仓库结构
- [ ] 跑过 `python scripts/check_banned_words.py examples/*.md`，案例本身不命中违禁词
- [ ] 中文标点统一，不混用英文标点

## Commit message

```
<类型>: <一句话>

类型：feat / fix / docs / words / examples
例：words: 补充医美行业功效词 12 条
```
